# Change evidence

Use only the fields that clarify the result.

- **Change and intended outcome:** What should a user observe?
- **Checked revision:** Commit or local state, including relevant uncommitted changes.
- **Evidence:** Claim → command or observation → actual result.
- **Failures and follow-up:** What failed, what was corrected, and what was rerun?
- **Gaps:** Checks not executed, unavailable prerequisites, and the smallest next step.

For a distributed skill, separate metadata validation, file installation,
and an actual agent invocation. These prove different things.
